### 📐 FORMATTING RULES (MANDATORY)
- Every bullet point MUST start with a past-tense verb (e.g. Added, Fixed, Removed, Updated, Improved).
- Use **bold** to highlight the component or area affected (e.g. **Auth Module**, **API Gateway**).
- Keep each bullet to a single line — no multi-line bullets.
- Use sentence case, not title case (e.g. "Fixed login timeout" not "Fixed Login Timeout").
- Do NOT use inline code ticks unless referencing an exact function or file name.
- Date format is strictly: YYYY-MM-DD.

---

### 🎙️ TONE & VOICE
- Write for a technical audience — developers, DevOps, and QA engineers.
- Be concise and factual. Avoid marketing language (e.g. "exciting", "revolutionary").
- Passive constructions are permitted but active voice is preferred.
